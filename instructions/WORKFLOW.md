# Workflow Instructions

## Branching

- Выполнять разработку в ветке `develop`.
- Вносить изменения в `master` только через слияние завершенной работы из `develop`.

## Development

- Перед изменениями изучать затрагиваемые код и конфигурацию.
- Сохранять изменения минимальными и соответствующими существующей архитектуре.
- Использовать Java toolchain, заданный в `build.gradle`.
- Не добавлять секреты, локальные файлы IDE и результаты сборки в Git.

## Verification

- После изменений запускать релевантные Gradle-задачи.
- Перед коммитом проверять `git status` и состав изменений.

## Documentation

- Фиксировать архитектурно значимые решения в `ARCHITECTURE.md`.
- Добавлять результаты завершенных этапов в `REPORT.md`.
